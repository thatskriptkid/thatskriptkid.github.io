### 10 Потенциальных классов уязвимостей

#### 1. **Недостаток проверки пути в `acmedesk://` URL**
- **Где искать**: Обработчик протокола `acmedesk://` в Electron-приложении.
- **Риск**: Атакующий может перейти на вредоносный путь, например `acmedesk://open?path=C:\Windows\system32\cmd.exe`.
- **Проверка**: Локально запустить приложение и ввести URL с подозрительным путем.
- **PoC**: В браузере или командной строке ввести `acmedesk://open?path=C:\Windows\system32\cmd.exe` и проверить, откроется ли файл.
- **Исправление**: Проверять, что путь находится в допустимой директории.

#### 2. **SQL-инъекция в SQLite**
- **Где искать**: Запросы к `data.db` в приложении.
- **Риск**: Атакующий может выполнить произвольный SQL-код.
- **Проверка**: Локально изменить данные в `data.db` и проверить, как приложение их обрабатывает.
- **PoC**: Вставить `'; DROP TABLE users;--` в поле, которое записывается в базу.
- **Исправление**: Использовать параметризованные запросы.

#### 3. **Небезопасное хранение токена**
- **Где искать**: Файлы конфигурации или база данных, где хранится токен.
- **Риск**: Токен может быть украден и использован для доступа к учетной записи.
- **Проверка**: Просмотреть файл `data.db` на наличие токена в открытом виде.
- **PoC**: Просмотреть содержимое `data.db` с помощью SQLite-браузера.
- **Исправление**: Хранить токен в зашифрованном виде.

#### 4. **Непроверенное обновление**
- **Где искать**: Скрипт `update.ps1`, который запускается для обновления.
- **Риск**: Атакующий может подменить `latest.yml` и установить вредоносное ПО.
- **Проверка**: Локально изменить содержимое `latest.yml` и проверить, будет ли оно загружено.
- **PoC**: Заменить `latest.yml` на файл с поддельным содержимым.
- **Исправление**: Проверять подпись файла обновления.

#### 5. **RCE через импорт `.zip`**
- **Где искать**: Обработчик импорта `.zip` файлов.
- **Риск**: Атакующий может вставить вредоносный файл, например `settings.json` с произвольным кодом.
- **Проверка**: Создать `.zip` файл с подозрительным содержимым и попробовать импортировать.
- **PoC**: Создать `.zip` с `settings.json`, содержащим вредоносный скрипт, и проверить его обработку.
- **Исправление**: Проверять содержимое `.zip` файла перед извлечением.

#### 6. **Проблемы с правами доступа**
- **Где искать**: Файлы и папки в `%APPDATA%\AcmeDesk\`.
- **Риск**: Атакующий может получить доступ к конфиденциальным данным.
- **Проверка**: Просмотреть права доступа к файлам и папкам.
- **PoC**: Попробовать прочитать `data.db` без прав администратора.
- **Исправление**: Ограничить права доступа к важным файлам.

#### 7. **Уязвимости в PowerShell-скрипте**
- **Где искать**: Скрипт `update.ps1`.
- **Риск**: Скрипт может выполнять небезопасные команды.
- **Проверка**: Просмотреть содержимое `update.ps1` на наличие уязвимых команд.
- **PoC**: Изменить скрипт, чтобы он выполнял вредоносную команду.
- **Исправление**: Проверять и ограничивать команды в скрипте.

#### 8. **Небезопасное использование Electron API**

- **Проверка**: Просмотреть исходный код на наличие уязвимых вызовов.
- **PoC**: Создать файл с произвольным содержимым и попробовать его открыть.

#### 9. **Проблемы с изоляцией процессов**

- **Риск**: Атакующий может получить доступ к другим процессам.
- **Проверка**: Просмотреть настройки изоляции в конфигурации приложения.
- **PoC**: Попробовать получить доступ к другим процессам через уязвимость.
- **Исправление**: Убедиться, что процессы изолированы.

#### 10. **Небезопасное хранение паролей**
- **Где искать**: Файлы конфигурации или база данных.
- **Риск**: Пароли могут храниться в открытом виде и быть украдены.
- **Проверка**: Просмотреть файлы на наличие паролей в открытом виде.
- **PoC**: Просмотреть содержимое `data.db` на наличие паролей.
- **Исправление**: Хранить пароли в зашифрованном виде.

### Checklist для тестирования custom protocol handler `acmedesk://`
1. Проверка обработки невалидных URL.
2. Проверка обработки специальных символов в пути.
3. Проверка доступа к файлам вне разрешенной директории.
4. Проверка выполнения произвольного кода через URL.
5. Проверка обработки длительных путей или символов, вызывающих переполнение буфера.

### Пример PowerShell-скрипта для сбора артефактов
```powershell
# Сбор файлов и их метаданных
$appPath = "$env:APPDATA\AcmeDesk"
$files = Get-ChildItem -Path $appPath -Recurse

# Создание отчета
$report = @"
[Файлы и папки в $appPath]
"@

foreach ($file in $files) {
    $report += "File: $($file.FullName)`n"
    $report += "Permissions: $(Get-Acl $file.FullName | Format-List | Out-String)`n"
    $report += "Hash: $(Get-FileHash -Path $file.FullName).Hash`n"
    $report += "Size: $($file.Length) bytes`n"
    $report += "LastWriteTime: $($file.LastWriteTime)`n`n"
}

# Сохранение отчета
$report | Out-File -FilePath "$appPath\report_$(Get-Date -Format 'yyyyMMdd').txt"

# Сбор версий бинарей
$binaries = Get-ChildItem -Path "$appPath\*" -Include *.exe, *.dll
foreach ($binary in $binaries) {
    try {
        $version = (Get-Item -Path $binary.FullName).VersionInfo
        $report += "Binary: $($binary.FullName)`n"
        $report += "Version: $($version.FileVersion)`n`n"
    } catch {
        $report += "Binary: $($binary.FullName)`n"
        $report += "Version: Not available`n`n"
    }
}

# Сохранение обновленного отчета
$report | Out-File -FilePath "$appPath\report_$(Get-Date -Format 'yyyyMMdd').txt"
```

### Выделение уязвимостей
- **Наиболее вероятные баги**: SQL-инъекция, непроверенное обновление, RCE через импорт `.zip`.
- **Самые критичные баги**: RCE через `acmedesk://` URL, непроверенное обновление.
- **Что нельзя утверждать без доступа к бинарю**: Точная реализация обработки URL, проверка подписи обновлений, наличие дополнительных механизмов защиты.
